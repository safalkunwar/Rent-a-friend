# SATHI Changelog

Last Updated: 2026-08-22

## Audit Summary (2026-08-22)

This changelog records findings from the complete project audit performed on 2026-08-22. No code changes were made during this audit.

### Current State

- **Overall Progress**: ~85%
- **Current Phase**: Phase 4 - Enterprise Admin Operations Platform
- **Firebase Project**: `hamrosathi1` (single source of truth)
- **Build Status**: Main app builds successfully; 145/146 tests pass (1 intermittent timeout)
- **Admin App**: Standalone at `/admin`, builds independently on port 3001

### Architecture

- Two separate applications: main app (`/src`) and admin app (`/admin`)
- Both share Firebase `hamrosathi1` but have separate entry points, routing, UI, and builds
- Main app: React + Vite + TypeScript + Tailwind CSS v4 + React Router DOM v7
- State: React Context (AppContext, ToastContext)
- Real-time data via Firestore subscriptions with IndexedDB offline cache

### Authentication

- Firebase Auth with email/password and Google Sign-In
- `browserLocalPersistence` for session persistence
- Custom claims for role-based access (customer, companion, admin)
- Profile restoration from Firestore on auth state change

### Firestore Collections (23 total)

`users`, `companions`, `bookings`, `conversations`, `messages`, `reviews`, `notifications`, `events`, `stories`, `activities`, `community_posts`, `likes`, `story_likes`, `comments`, `favorites`, `booking_locks`, `presence`, `guideApplications`, `reports`, `sosAlerts`, `suspiciousActivity`, `admins`, `auditLogs`

### Home Feed

- Mixed discovery feed generated by `generateDiscoveryFeed()` in `src/services/feedGenerator.ts`
- NOT a rigid Companion → Event → Activity pattern
- Per-type caps: companion 30%, activity 20%, event 20%, story 15%, post 15%
- Category-based grouping with random shuffling
- Content types mixed within each category section

### Pagination / Loading

- `useFirestoreData` hooks accept `page` parameter, scaling `limitCount` (e.g., `30 * page`, `20 * page`)
- `useDiscoveryFeed` scales `maxItems` (60 * page), `categoriesPerFeed` (min(3+page, 6)), `itemsPerCategory` (min(6+page*2, 12))
- Progressive loading via sentinel element: desktop `DiscoveryFeed` and mobile `ClientApp` both increment visible category count on scroll
- **No cursor-based pagination**: `page` scales limits but does not use `startAfter` cursors
- Realtime subscriptions via `onSnapshot`, not one-time queries

### Desktop / Mobile

- **Desktop**: Fixed left sidebar (256px) + main content + optional right sidebar (`xl:`)
- **Mobile**: Single column + bottom navigation (5 tabs) + sliding profile drawer
- Both use same data hooks and feed generation logic
- Mobile home tab has additional static sections not in desktop `DiscoveryFeed`:
  - "Activities" horizontal scroll section
  - "Upcoming Events" list
  - "Become a Companion" CTA banner
